# v3.2.7 · HID 兼容与输入修复

- PS5 模式在输入暂停时，每次空闲 HID 读请求最多等待 100ms 后提供兼容报告，避免客户端一直等下一帧。保留按键与重力值，停止重放旧角速度；兼容报告单独计数，不计入真实 FD2 输入。
- 修复 USBIP 正常完成与 UNLINK 取消的竞争：取消成功后，不再重复提交同一请求的正常完成。
- 初始化应答按当前特征、命令和 Flash 地址匹配，避免旧应答提前结束下一条命令。
- 普通背键／C 键长按在短暂输入间隙后保持连续；达到 500ms 时释放。连发、顺序按键与触控手势遇到间隙后取消，松开再按才重新开始。
- 有线与 Pro1 HID 输入队列保留按下、松开和扳机开关边沿，只合并相邻、按键状态相同的摇杆更新。Pro2 BLE 已有的边沿保留继续使用。
- 高速验收与健康监测统一采用 128Hz 容差；60Hz 可游玩，120Hz 只用于保留已生效的 7.5ms 连接，不作为已达 133Hz 的证明。
- 参数预设尚未发出、仅测量未完成时，保留手动重试入口；自动重试间隔至少 30 秒，每条连接最多两次未完成测量，避免无限重试。
- PS5 反馈空闲改为保留单个读任务与定时节拍，不再每 40ms 创建超时异常。

## 验证结果

- 应用层 931643 项离线／本机回环断言通过；包含实际生产状态机的 ACK、背键、HID 短按、125Hz 状态与反馈空闲回放。
- Go 后端全量测试通过，包含 100 组取消与正常完成竞争测试。
- Windows 原生 HID 对照：旧后端在无新输入时，清队列后的读操作超过 750ms 未完成；新后端 30 轮清队列／读取／取消测试通过。实测清队列最长 0.92ms、空闲读最长 97.50ms、取消或正常完成最长 26.37ms。这些是本机观测值，不是跨电脑的实时保证。
- Windows 测试使用同一 DualSense HID 实现，未启用音频接口、未使用实体手柄；临时 USBIP 设备和测试进程已清理。最终独立 EXE 的界面启动检查通过。

本次没有重启蓝牙、改驱动、注册表或配对。尚未完成 UU 4.47.x 窗口激活／失活场景的端到端复测，不能据此承诺解决其全部挂起原因。没有把 `HidD_FlushQueue` 本身认定为已复现的死锁点；本机旧版对照卡在其后的 HID 读取。

## 对外部审核意见的取舍

已修复能从源码与回放确认的缺陷。Pro2 BLE 的边沿保留原本就已存在；有线／Pro1 HID 路径才是本次补齐对象。单独的 COM 包装器被回收，不等于投影对象已经失效；未将该推断作为已确认的释放后使用问题。保留多手柄环境隔离的缓存键，不擅自更换未经协议验证的 IMU 校准格式或震动参数。

协议参考：[USB/IP 取消语义](https://docs.kernel.org/usb/usbip_protocol.html)、[微软 HID 清队列接口](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidsdi/nf-hidsdi-hidd_flushqueue)。
