# PRO2 手柄助手 v3.2.2 · 待机后蓝牙连接恢复

- Windows 待机时暂停新的 Pro2 BLE 连接尝试；系统恢复后等待 3 秒，再由原来的重连流程接管。已恢复正常输入的会话继续使用，不自动重启适配器。
- 首页对 GATT 不可达、请求超时和长期未释放的请求显示“恢复蓝牙连接”。确认并授权后，先退出旧助手以释放它持有的 Windows 蓝牙对象，再禁用／启用所选适配器，重开助手并按原槽位尝试连接。
- 超时不视为 Windows 已取消请求。诊断保留具体阶段、待处理时间和最终设备状态，不继续叠加连接请求，也不将适配器重新启用视为手柄已经恢复 133Hz。
- 恢复前备份设备驱动信息与现有 BLE 参数，并生成仅重新启用同一设备的恢复脚本。保留驱动包、BLE 参数与配对；不中断其他适配器，但所选适配器上的耳机、鼠标、键盘等会暂时离线，助手的游戏输出也会中断。
- 若禁用、启用或设备状态核实失败，不自动重复尝试；若 Windows 返回 3010，明确提示仍需重启 Windows。恢复脚本与详细记录路径显示在“系统与蓝牙信息”。

使用：退出旧版，打开本 EXE。若仍显示不可达，点击首页“恢复蓝牙连接”，核对适配器并批准一次管理员授权。恢复过程中等待窗口关闭、助手重新打开；手柄需要保持可连接。

验证：编译通过；929768 项离线断言通过，包含四槽位恢复票据、主流适配器标识校验、失败／取消后的重新启用、3010 判定、挂起请求释放与界面检查。未在本轮执行真实适配器禁用／启用，也未完成待机故障的实机恢复验收；不能据此保证所有驱动免重启或达到 133Hz。

工程记录：本机旧版日志能收到新鲜 Pro2 广播，但 GATT 服务发现返回 Unreachable；此前的用户手动重启适配器返回 3010，之后出现 Windows 打开设备请求超时且长期未释放。现有证据不能单独证明某一家驱动故障或控制器被其他设备占用。
