# v3.2.3 · BLE 预设保留与 FD2 验收修复

- 修复最终窗口仍可游玩，却因比最佳试验低 2Hz 以上而被退回低速原连接的问题。本机旧日志实测 70.09 → 67.90Hz，随后被撤销到 9.69Hz，导致连接验收失败。
- 最终输入仍达到 60Hz、优于原连接且新鲜度、解析和间隙检查通过时，保留兼容方案。高速验收标准不放宽，不把 60～70Hz 标成 133Hz。
- 最终窗口发生断联时清除历史方案，不拿历史频率当当前成功。新增 `final_playable_preserved` 与明确的 FD2 验收结果、回调耗时记录，避免只显示 `operation_failed`。
- 现有诊断 CLI 可用 `--ble-diagnostic --ble-adaptive-presets --duration 60` 复用正式预设路径测真实输入；不创建虚拟输出、不改驱动或注册表。

验证：929790 项离线断言通过，包含本次完整测量重放及陈旧输入、解析失败、卡顿、原生更好、断联与缓存边界检查。

2026-11-15 本机 Windows 11 26300.9974、Realtek 0BDA:0852 / 18.4032.2510.900、Pro2 固件 1.1.5 实测：原生 16.69Hz；固定 7.5ms 两段窗口 132.89 / 133.11Hz；随后 60 秒 Raw / FD2 / Parsed 均 132.87Hz，7973 条报告全部解析，P50 7.50ms、P95 8.00ms、P99 8.94ms，最大间隙 35.66ms，连接连续，退出码 0。此次未重启适配器、未改驱动或注册表；诊断窗口未启动虚拟手柄，运行中电量查询按诊断策略关闭，连接前电量快照保留。

范围：已证实策略回退漏洞，并恢复了一轮真实高速输入验收。历史 68Hz 的传输瓶颈为何在新一轮消失，证据不足，不能单独归功于代码修复。完整 GUI／游戏输出、长时间待机与跨机器稳定性不由这 60 秒证明。工程交接包保留前后日志与测量 JSON，便于继续追查。
