# 新和联胜三合一控制中心：公开测试版使用说明

English: [THREE_IN_ONE_R40_TEST_EN.md](THREE_IN_ONE_R40_TEST_EN.md)

## 先读这段

这是把三条既有路线放入统一入口的 **三合一测试版**，不是把三条通信链路改写成一个固件，也不是所有设备都已经验收通过的正式稳定版。本次暂停继续优化，按现有原包发布；仍可能出现配对失败、断电后回连失败、震动异常、陀螺仪体验差异等问题。旧版下载保留，遇到回归可退回之前适用的版本。

下载主程序：`XinHeLianSheng-Three-In-One-R40-test.exe`，即原来的 `新和联胜三合一控制中心-R40-test.exe`，只为下载使用英文文件名，内容不变。Windows 10/11 x64，界面目前为中文。文件约 514 MiB，因为内置了四个独立后端程序及其运行环境。首次启动后端需要解包和校验，请等待，勿重复点击。

**内置 Pico 固件仍是 R40，不是 R55。** 本次另附 R55 UF2，供愿意继续排查配对问题的用户手动刷入；它不是三合一的默认固件，也没有完成全面稳定性验收。

## 三条路线如何选

| 入口 | 实际内置版本 | 输入与输出 | 适合谁 |
| --- | --- | --- | --- |
| Pico 2 W 背挂 | R40 候选刷机工具 | Pro2 有线 USB → Pico USB Host → 目标设备蓝牙 | 已准备 Pico、Host 接线及稳定 5 V 供电的背挂原型用户 |
| ESP32-S3 接收板 | V5.9.19 候选 | Pro2 BLE → ESP32-S3 → 目标设备 USB | 使用既有 ESP 接收板的用户 |
| ESP 的 Switch 1 实验入口 | V5.9.18 Switch 1 R4 | Pro2 BLE → ESP32-S3 → Switch 1 USB | 愿意测试一代 Switch 兼容性的用户 |
| 纯软件直连 | V6.2.32 Test R2 | Pro2 BLE → Windows → VIIPER / USBIP 虚拟 USB | 不想使用开发板的 Windows 用户 |

三条路线只选一条使用。先关闭旧 Manager、另一个刷机工具、串口监视器以及不使用的虚拟手柄程序；测试纯软件时，也拔掉其他手柄桥接板，避免 Steam 同时看到旧设备。

控制中心会管理它自己启动的一个后端：再次启动同一后端会显示已有窗口，切换另一后端时会要求先关闭原后端。**这不是全系统进程锁**，不能阻止你在别处手动打开旧程序。“结束后端”只请求正常关闭，不会强杀刷写过程。关闭控制中心也不等于已经关闭后端，请先结束后端的游戏会话或刷机操作。

## 路线一：Pico 2 W

### 硬件与刷写

Pico 读取的是 **真实 Pro2 的有线 USB 输入**，不是连接 Pro2 的蓝牙。Pro2 接外置 USB Host 口，Pico 自身的 micro-USB 接电脑用于刷写和串口诊断；后者不是一个有线 DualSense 输出口。

使用已经验证的 Host 接线与稳定的 5 V 电源。Pico 2 W 本身不具备锂电池充电管理，也不能把裸 3.7 V 电池直接变成合规的 USB 5 V。不要在电源接法不明时同时接入多个电源；调整接线先断电。本说明不取代硬件接线图。

1. 断开 Pro2，关闭背挂外置电源，只把 Pico 自身 USB 接入 Windows 的数据线。
2. 在控制中心选 Pico 入口，启动刷机工具。
3. 已有固件和串口正常时，可点击自动进入 BOOTSEL。
4. 自动方式失败，按住 Pico 的 BOOTSEL，再插入电脑 USB，松开按键。
5. 应识别到 `RP2350` 磁盘。`RPI-RP2` / RP2040 / Pico 1 不兼容，不要刷入。
6. 点击“开始刷入内置固件”，等待 `firmware_revision=r40`、`runtime_ready=true` 的验证；不要仅凭磁盘消失判断成功。
7. 验证后恢复背挂供电并把 Pro2 接回 Host 口，再在目标设备蓝牙界面配对。

刷写通常保留保存的模式和绑定资料。产品默认是 Edge，但已有保存模式会优先，不能假定每次刷写都会切回 Edge。

### 四种无线模式

Pro2 已有 USB 实时输入时，按住 **GL + GR + ZL + ZR**，再加入下列一个按键，整体保持约 **1.5 秒**：

| 选择键 | 模式 | 通常看到的蓝牙名称 | 功能边界 |
| --- | --- | --- | --- |
| A | PS5 / DualSense | Wireless Controller | 按键、摇杆、陀螺仪及普通震动实现；仍有兼容性问题 |
| B | PS5 Edge | DualSense Edge Wireless Controller | 加入背键身份；普通震动、陀螺仪仍需目标应用支持 |
| X | Xbox BLE | Xbox Wireless Controller | 普通震动；此协议不提供陀螺仪 |
| Y | Switch 1 Pro | Pro Controller | 一代 Switch 蓝牙实验路线，连接与震动未全面验收 |

GL / GR 是两颗背键，Plus / Minus 是 + / − 键。避免同时加入多个选择键。切换身份会断开旧主机，目标系统可能还保留旧名称；保存过多种名称不代表 Pico 正在同时给多个主机发送输入。当前固件设计为一个活动模式、一个活动主机。

要恢复 Pro2 原生模式 / 连接 Switch 2，最可靠的方式仍是 **物理拔掉 Pro2 的 Type-C**。红色 VBUS 线常通的原型不能只靠软件“静默”实现真正拔线。

### 配对、换电脑与重连

1. Windows / Android / Apple 设备打开蓝牙，添加当前模式名称的控制器。平台与应用兼容性属于测试目标，并非全部已验证。
2. 新模式没有绑定时，R40 会持续开放配对；已有绑定时会交替回连旧主机与开放发现，因此扫描不一定一直显示同一状态。
3. 换新主机或密钥失配时，长按 **GL + GR + ZL + ZR + Plus + Minus 约 2 秒**，清除当前模式绑定并重新开放配对；其他模式记录不随之清除。该组合键不会强制切成 Edge。
4. 同时在目标系统删除当前控制器的旧蓝牙记录，再重新搜索。电脑上其他同名控制器要确认不是另一块开发板。
5. 正常应免 PIN 配对；R40 的旧式兼容 PIN 为 `0000`。若仍要求 PIN 或一直无响应，可能是旧绑定或安全协商问题，不应靠反复猜密码解决。保留日志，重新开放当前模式配对后再试。
6. 组合键需要真实 Pro2 输入已到 Pico；如果 USB 输入停了，组合键本身也无法生效，可使用 Pico 诊断串口或物理 BOOTSEL 恢复。

平台操作：Windows 在“蓝牙和设备 → 添加设备 → 蓝牙”选择当前身份；Android 在蓝牙设置中配对，再用支持游戏手柄的游戏验证；macOS 在系统设置的蓝牙中连接，iPhone / iPad 在设置的蓝牙中连接，是否支持 Edge 与系统版本 / 应用有关。Switch 1 先切 Y 对应的 Pro 模式，进入“控制器 → 更改握法 / 顺序”，再触发当前模式配对；不能只拿 Windows 搜到 Pro Controller 当作 Switch 验收。Pico 的蓝牙运行不需要电脑安装 USBIP 或 VIIPER。

轻微震动反馈依赖 Pico → Pro2 震动通路；没有震动不能单独证明组合键未触发。Pro2 黄灯是充电 / 活动提示，熄灭也不能单独证明断联，诊断以 `USB_HEALTH` 的报告计数和 `wireless status` 为准。

**不支持实体 Xbox 主机的 Xbox Wireless 协议，也没有实体 PS5 主机所需的首次 USB 配对 / 认证。** “PS5 / Edge”表示兼容身份，不是官方认证。Pico 不模拟音频设备，不提供 DualSense 音频 HD haptic、耳机或麦克风转发。

### 可选 R55 恢复固件：不是内置版本

文件：`XinHeLianSheng-Pico2W-Pro2-Wireless-Bridge-test-r55.uf2`。

它用于继续排查 Sony 模式配对：首次运行 R55 恢复标记时选择 Edge，并清除 Edge 的旧绑定；后续启动保留新绑定和选定模式。同一份 R55 再刷一次，不保证重新触发首次恢复，因为标记可保存在闪存中。

手动进入 BOOTSEL，把这份 UF2 复制进 `RP2350` 磁盘。此后若点击三合一 Pico 工具的“刷入内置固件”，**会重新刷回 R40**。R55 是单独的实验资产，不要把工具里的 R40 标识当成 R55 验证结果。

R55 完整 Sony 蓝牙报告目前限速约 66 Hz，这是发送上限，不等于真实输入频率测量值。USB 输入可以更快，但不能据此宣称蓝牙端已经达到 250 Hz。R55 已通过构建及已有源码契约检查；本次没有完成配对、持续输入、震动和 IMU 的整机验收，不能承诺它解决全部连接问题。

## 路线二：ESP32-S3 接收板

### 第一次使用与日常使用

1. 使用适配既有固件的 ESP32-S3 板，不要假定任意 ESP 板都兼容。COM 控制口负责刷写 / 查询，原生 USB / OTG 口负责输出虚拟手柄。
2. 首次使用把 COM 接电脑，也把原生 USB 接目标电脑以便验证身份。选正确 CH343 / WCH 串口，不要选择蓝牙虚拟 COM。
3. 启动 ESP 入口，选择模式并刷写对应固件。切换模式是重新刷固件，不是 Pico 的组合键切换。
4. 等待刷写完成，再检查 USB 身份；必要时重新插拔原生 USB / OTG，不要在刷写中拔 COM。
5. 唤醒 Pro2 并按其配对键，使用“首次连接”或 BLE 扫描后手动选择连接。首次配对期间避免它同时连 Windows、Switch 或其他桥接板。
6. 确认有实时按键 / 摇杆数据，再进入游戏。已保存 Pro2 地址后，日常通常只接原生 USB 即可供电并自动回连；COM 用于管理和诊断，不是每日必需。

| 固件身份 | 识别标记 | 说明 |
| --- | --- | --- |
| PS5 / DualSense | 054C:0CE6 | PS5 兼容输入、陀螺仪；有支持游戏提供音频 HD haptic 的路线，并协调普通震动 |
| PS5 Edge | 054C:0DF2 | Edge / 背键身份；震动和 IMU 仍以固件配置及主机支持为准，不承诺所有 PS5 游戏原生识别 |
| Nintendo / Pro2 | 057E:2069 | 面向 Steam 的 Pro2 兼容布局，部分游戏需 Steam Input；不是 Switch 2 认证承诺 |
| Xbox / XInput | 045E:028E | 广泛 PC 按键 / 摇杆支持，普通震动，无 XInput 陀螺仪 |
| macOS 标准 HID 候选 | CAFE:4037 | 额外 HID 输入路线，不等同于所有平台完整功能 |

HD haptic 需要游戏真正给对应端点发送触觉音频；不是把系统所有声音当震动。音频端点、游戏支持、Steam Input 设置都会影响结果。背键映射按 Xbox 页面允许的键位、单发 / 连发选项操作，不是任意脚本引擎。

### Switch 1 独立实验入口

控制中心的 ESP 卡片另有 Switch 1 入口，内置 **V5.9.18 R4**，与 V5.9.19 分开保留。它输出 `057E:2009` 一代 Pro USB 身份。

把 COM 留在电脑管理、原生 USB 接 Switch 1；主机中启用“Pro 手柄的有线通信”，必要时在控制器界面更改握法 / 顺序，再让真实 Pro2 与 ESP 配对。该路线仍属连接和震动实验，不承诺已消除所有重连或固件崩溃。

### 刷写失败时

`Wrong boot mode` 表示没有进入 ROM 下载模式，不等于开发板一定损坏。可按住 BOOT，按下再松开 RESET / EN，再按工具提示重试。拒绝访问表示串口可能被其他程序占用。若驱动出现内核级挂起，停止反复打开串口，按诊断提示重新插拔 / 重启及使用适配驱动；不要随机轮换驱动、关闭签名保护或在刷写中强杀。

ESP 实际 BLE 输入频率受 Pro2、无线环境和固件参数约束。约 133 Hz 是此前条件下的参考值，不是任意电脑 / 多手柄下的保证，也不代表虚拟 USB 刷新都是新采样。

## 路线三：Windows BLE / VIIPER

### 首次安装

本路线不需要开发板，**但需要 Windows 系统级 USBIP 驱动**。VIIPER 运行程序和 usbip-win2 安装器已内置，VIIPER 不需要另行安装；USBIP 内核驱动不能靠把 EXE 复制到电脑就自动具备。

1. 使用 Windows 10/11 x64 与支持 BLE GATT 的蓝牙适配器，打开系统蓝牙。无线测试时拔掉真实 Pro2 的电脑 USB。
2. 启动纯软件入口，按环境检查提示点击“安装 / 修复 usbip-win2”，确认 UAC 和安装向导。
3. 安装器或程序提示重启时，重启 Windows 再继续。安装成功的文件路径不等于驱动已经加载。
4. 程序会从注册表、PATH 和常见目录查找 USBIP。没有安装登记、未加入 PATH 且在非常规目录的便携复制可能识别不到；失败时优先使用内置正式安装器，不要反复安装 VIIPER。
5. 选择模式，点击“进入游戏”，先确认虚拟 USB 手柄建立成功，再等待 / 操作 Pro2 自动连接。
6. Pro2 由程序作为 BLE central 直接读取，**不要要求它先在 Windows“添加蓝牙设备”里完成 HID 配对**。唤醒手柄并进入配对模式；自动流程未找到时再使用手动扫描 / 连接区。

### 模式与四个独立槽位

| 模式 | 用途与边界 |
| --- | --- |
| PS5 / DualSense | 兼容输入、陀螺仪、普通震动；HD haptic 需支持游戏和对应音频流，不保证每个游戏都有 |
| PS5 Edge | 背键身份、陀螺仪、普通震动；此包 Edge HD 状态仍为 `blocked_by_viiper_feedback_contract`，不要按 HD 已打通理解 |
| Pro2 / Nintendo | Steam 原生兼容路线、陀螺仪、支持的 Nintendo 震动反馈；部分游戏必须启用 Steam Input |
| Xbox / XInput | 广泛兼容，无 XInput 陀螺仪；Xbox 页面允许为 GL / GR 设置规定键位的单发 / 连发映射 |

后端支持最多四个独立槽位：每槽绑定不同真实 Pro2 地址，建立独立虚拟实例，并把输入与震动回传到对应手柄。不要把同一实体手柄重复填进多个槽。本次没有进行四实体手柄的完整并发验收，无线带宽和蓝牙适配器会影响并发效果。

如 Steam 显示额外同名手柄，先检查其他后端、真实有线设备、ESP 或旧虚拟实例，不要只靠显示名称判断身份；结合 VID/PID、布局和槽位日志确认。

BLE 采样率与虚拟 USB 输出不是同一指标；本包采用输入源驱动的正常推送路线，不以强制重复 250 Hz 帧证明低延迟。Windows 下此前常见约 60–80 Hz，但不是所有 Windows 11 的固定上限，具体看当次 telemetry。

后端的自动重连、托盘 / 上次模式选项按界面操作；要停止自动连接请明确关闭对应开关或停止会话。游戏侧 Steam Input 与原生手柄输入选其一测试，避免双层映射影响震动、键位或 IMU。

### 摇杆校准

V6.2.32 R2 包含两种校准：零位时完全松开两根摇杆并静置约 2 秒；完整行程时在约 8 秒内让两根摇杆覆盖上 / 下 / 左 / 右，并沿外圈转动多圈，等完成提示。校准结果按手柄地址保存。它能校正中心 / 行程差异，不应被用来掩盖坏包、错误布局或硬件损坏。

## 已知问题：发布时仍然保留

- Pico 某些模式切换或新设备配对会出现可发现但连不上，等待较长时间后才恢复；断电 / 长待机后也可能回连失败。
- Pico PS5 / Edge 的 Steam 测试震动可能无反应，游戏触发后可能持续震动；R40 有停振状态机实现，但不能据此宣称现场问题已全部解决。异常时停止游戏会话，必要时断开桥接供电。
- Pico 与 ESP 的 Switch 1 实验身份，可能出现发现后无法连接或重连异常，普通震动尚需专项验收。
- 陀螺仪转换已有实现，不能承诺所有游戏与真实有线 Pro2 等效；Edge 被游戏接受按键但忽略 gyro，也可能是游戏只支持标准 DualSense 的兼容差异。
- Windows USBIP 驱动权限、安装后未重启、蓝牙适配器兼容性、无线干扰都可能导致失败。日志不能总是区分没电、主动关机与异常离线。
- 当前测试 EXE 未承诺商业代码签名；下载后核对 SHA256。不要关闭系统安全措施来强行运行来源不明的文件。
